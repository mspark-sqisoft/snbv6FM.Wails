# 디자인 5종 규격

앱 안에서 바로 바꿔 쓰는 디자인 다섯 가지를 정의한다. 기존 디자인은 `기본`으로 남고, 라이트·다크 선택은 `기본`에서만 쓴다.
다섯 디자인은 각자 고정된 밝기를 가진다. 색만 바꾼 스킨이 아니라 메뉴·표·상태 표시의 생김새가 서로 달라야 한다.

## 앱에서 가져온 은유

snbApp 은 서로 끊어진 두 망 사이로 파일을 건네는 앱이다. 파일은 검사를 받고, 사람의 결재를 받은 뒤에야 반대편 망으로 건너간다.
다섯 디자인은 이 "건너감·검문·승인" 을 각기 다른 현실의 장소에 빗댄다.

| id | 이름 | 밝기 | 은유 | 왜 이 앱에 맞는가 |
|---|---|---|---|---|
| `airlock` | 에어록 | 어두움 | 두 공간을 잇는 이중 잠금문 | 망분리는 양쪽 문이 동시에 열리지 않는 통로다 |
| `gongmun` | 공문 | 밝음 | 기안 용지와 붉은 인주 | 결재가 이 앱의 중심이고 고객이 공공·금융 조직이다 |
| `departure` | 출발 안내판 | 어두움 | 공항 출발 안내판 | 파일은 항공편, 반대편 망은 목적지, 상태는 탑승 현황이다 |
| `waybill` | 운송장 | 밝음 | 화물 터미널의 운송장 라벨 | 파일을 화물처럼 맡기고 받는 사람이 찾아간다 |
| `metro` | 노선도 | 밝음 | 지하철 노선도 | 올리기·검사·결재·전송·받기가 정거장처럼 이어진다 |

## 다섯 디자인의 세부

### 에어록(`airlock`)

- 색: 밤 강철 `#0D1117` 면에 업무망 보라와 인터넷망 청록의 빛이 창 양쪽 가장자리에서 들어온다. 경고 호박 `#F5A524` 는 위험한 곳에만 쓴다.
- 형태: 패널 모서리를 둥글리지 않고 깎는다(`clip-path`). 45도 경고 줄무늬는 위험 동작과 전송 중에만 나타난다.
- 서명 요소: 머리줄 아래 띠에 망 A, 잠금문, 망 B 를 그리고 전송 중이면 문 사이로 점이 흐른다.
- 로그인: 닫힌 두 짝 문과 가운데 봉합선을 그린다. 접속 중이면 문이 벌어진다.

### 공문(`gongmun`)

- 색: 한지 `#F6F1E4`, 먹 `#1F1B16`, 쪽빛 `#1F3A5F`(주 단추), 인주 `#B3261E`(표지·도장·위험).
- 글꼴: 제목은 고운바탕, 본문과 표는 판독성을 위해 Pretendard 를 유지한다.
- 형태: 둥글기 0, 그림자 없음. 표는 세로 괘선과 이중 머리선을 쓰는 기안 용지 형식이다.
- 서명 요소: 상태 칩은 틀만 살짝 기운 인장으로 그리고 글자는 바르게 둔다. 머리줄 오른쪽에 담당·전송·승인 칸이 있는 결재란을 둔다. 왼쪽 메뉴는 문서철의 색인 탭이다.
- 결재란: 전송 칸은 도장 없이 진행 건수나 실패 건수를 글자로 적는다. 승인 칸의 값은 권한이지 승인 사실이 아니다. 도장은 실제로 일어난 사건(로그인)에만 찍는다.
- 로그인: 기안 용지 위에 입력 칸이 놓이고, 접속에 성공할 때 도장이 찍힌다.
- 색의 뜻: 찍힌 상태만 면을 채운다. 성공은 쪽빛 인장, 실패는 인주 인장이다. 대기는 곧은 점선, 중립은 얇은 선이다. 초록을 성공 색으로 쓰지 않는다.

### 출발 안내판(`departure`)

- 색: 보드 `#0B0B0C`, 앰버 LED `#FFB000`, 안내 표지 노랑 `#FFD400`(검정 글자), 정상 `#39D353`, 경고 `#FF5A4F`.
- 글꼴: 제목과 표 머리는 Galmuri11 도트 글꼴, 표 본문의 한글은 Pretendard, 숫자는 고정폭 글꼴이다.
- 배치: 상단 탭을 강제하고, 탭은 공항 안내 표지처럼 노란 띠에 검정 글자로 그린다.
- 서명 요소: 표의 행을 플립 보드처럼 가운데 경첩선이 있는 칸으로 그린다. 머리줄에 시계와 목적지 망을 보드로 띄운다. 상태가 바뀐 칸은 뒤집히며 바뀐다.
- 로그인: 빈 출발 안내판에 망 목록이 항공편처럼 뜬다.

### 운송장(`waybill`)

- 색: 크라프트 `#C9AE85` 바탕, 라벨 `#FBF8F1`, 먹 `#1A1A1A`, 안전 주황 `#F05A00`.
- 글꼴: 28px 이상 큰 제목은 Black Han Sans, 그보다 작은 제목은 본문 글꼴 800, 코드·수치는 IBM Plex Mono 다. 22px 이하에서는 ㅍ·ㄹ 의 속이 막힌다.
- 형태: 패널은 흰 라벨이고 가장자리에 점선 절취선과 구멍이 있다. 위험 동작에는 사선 테이프를 두른다.
- 서명 요소: 화면 제목 옆에 화면 id 로 만든 바코드를 그린다. 상태 칩은 `취급주의` 라벨 형식이다.
- 로그인: 빈 운송장의 보내는 곳·담당 칸이 망 선택과 ID 입력을 겸한다.

### 노선도(`metro`)

- 색: 흰 바탕, 먹 `#111111`, 업무망 노선 `#6A2FC9`, 인터넷망 노선 `#00A5A0`, 보조 노선 노랑 `#F2A900`, 빨강 `#E6002D`, 초록 `#00A84D`.
- 형태: 굵은 선과 둥근 정거장만으로 구조를 그린다.
- 서명 요소: 왼쪽 메뉴를 세로 노선으로 그린다. 메뉴 항목이 역이고 지금 화면은 환승역 표시다. 진행 막대에 정거장 점이 찍힌다. 화면 제목은 역명판 형식이다.
- 로그인: 두 망이 환승역에서 만나는 노선도를 그린다.

## 공통 규칙

### 기능을 바꾸지 않는다

- 디자인은 보이는 모습만 바꾼다. 문구, 단추의 뜻, 표의 열, 단축키, `id`, `aria-*` 는 그대로 둔다.
- 띠·로그인 그림에 넣는 값은 실제 상태만 쓴다. 가짜 수치·가짜 진행률을 그리지 않는다. 데이터가 없으면 비워 둔다.
- 장식은 `aria-hidden="true"` 를 붙인다. 정보를 장식에만 담지 않는다.

### 읽을 수 있어야 한다

- 본문 글자와 표 글자는 면 대비 4.5:1 이상이다. `npm run check:designs` 가 토큰 대비와 토큰 누락을 검사한다.
- 표 본문 글자는 13px 아래로 줄이지 않는다. 도트·장식 글꼴은 제목과 짧은 라벨에만 쓴다.
- 상태는 색이 아니라 글자로도 구분된다. 위험·경고·성공은 같은 디자인 안에서 서로 다른 색으로 보인다.
- 포커스 표시는 모든 디자인에서 눈에 보여야 한다. 키보드로 조작이 가능해야 한다.
- `prefers-reduced-motion` 이면 움직임을 끈다.

### 성능과 배포

- 그림은 CSS·인라인 SVG 로 그린다. 이미지 파일을 쓰지 않는다.
- 웹 글꼴 주소를 쓰지 않는다. 고객 망은 인터넷이 닿지 않으므로 글꼴은 npm 패키지로 번들한다.
- 움직임은 `transform`·`opacity` 만 쓴다. 표의 행 수와 비례해 늘어나는 장식 요소를 만들지 않는다.
- `backdrop-filter` 와 큰 면적의 `filter` 를 쓰지 않는다.

## 구조

```
frontend/src/designs/
  registry.ts           디자인 목록(id, 이름 번역 키, 밝기, 강제 배치, 색 미리보기)
  index.css             각 디자인의 css 를 모은다
  <id>/design.css       :root[data-design='<id>'] 아래의 토큰과 컴포넌트 재정의
  <id>/Art.svelte       로그인 화면 왼쪽 그림(선택)
  <id>/Strip.svelte     머리줄 아래 띠(선택)
```

- 적용: `html[data-design]` 에 id 를 넣고 `html[data-theme]` 에 그 디자인의 밝기를 넣는다. `기본` 은 `data-design` 을 지우고 기존 테마 규칙을 따른다.
- 저장: 설정의 `design` 값(문자열)에 저장한다. 처음 값은 `standard` 다.
- 선택: 설정 화면의 카드 묶음과 머리줄·로그인 화면의 단추 메뉴에서 고른다.
- 컴포넌트 재정의: Svelte 의 지역 CSS 는 클래스 이름을 유지한다. 그래서 `:root[data-design='metro'] .side .item` 처럼 전역 CSS 로 덮어쓸 수 있다.
  컴포넌트 파일의 `<style>` 은 고치지 않는다. 덮어쓸 수 없는 구조가 필요하면 컴포넌트에 클래스나 슬롯을 더한다.
